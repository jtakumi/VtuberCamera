## Documentation Standards

### File Naming
- Use UPPER_CASE_WITH_UNDERSCORES for documentation files
- Use descriptive names that clearly indicate content
- Add appropriate file extension (.md for Markdown)

### Content Guidelines
- Include table of contents for longer documents
- Use code blocks with language specification
- Include visual diagrams where helpful
- Provide both Japanese and English for user-facing docs
- Keep technical documentation up-to-date with code

### Markdown Best Practices
- Use headers hierarchically (h1 → h2 → h3)
- Include emoji for visual distinction (optional)
- Use code fences with language hints
- Add links to related documentation
- Include examples and screenshots where relevant

## Contributing to Documentation

When adding new features:
1. Create technical documentation describing the implementation
2. Create user guide if the feature is user-facing
3. Update flow diagrams if architecture changes
4. Add quick reference snippets for developers
5. Update this README with new documentation links
